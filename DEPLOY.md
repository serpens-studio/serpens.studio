# Serpens Studio — build & Dokploy deployment

Static site generated by `build.py`. nginx serves the pre-rendered output.

```
build.py                  generator: emits ./dist
verify.py                 post-build checks (links, SEO head, JSON-LD, sitemap)
site-src/
  home.html               long-form home body; every sub-page lifts sections from it
  home-schema.json        home page JSON-LD graph
  main.css  main.js       shared assets
  img/                    copied to dist/img/  (30-day cache)
  static/                 copied to dist/      (og.png lives here)
nginx/site.conf           server config used by the image
Dockerfile                stage 1 builds the site, stage 2 serves it
docker-compose.yml        local preview / optional compose deploy
```

## Local

```bash
python3 build.py && python3 verify.py     # no dependencies beyond python3
python3 -m http.server -d dist 8000       # rough preview (no clean-URL redirects)

docker compose up --build                 # true preview, exactly what deploys -> :8080
```

`verify.py` fails on dead links, missing or duplicate titles/canonicals, invalid
JSON-LD, leaked TODOs, and unresolvable sitemap entries. Warnings don't fail.

## Configuration

Config is read by `build.py` and exposed as Docker **build args**. The site is
static, so values are baked in at build time; runtime env vars do nothing.

| Build arg | Default | Effect |
|---|---|---|
| `SITE_BASE_URL` | `https://serpens.studio` | canonical tags, `og:url`, JSON-LD `@id`, `sitemap.xml`. No trailing slash. |
| `SITE_PHONE_DISPLAY` | `(602) 905-7835` | visible phone, all pages |
| `SITE_PHONE_TEL` | `+16029057835` | `tel:` links, all pages |
| `SITE_EMAIL` | `hello@serpens.studio` | mailto links, JSON-LD, form fallback |
| `SITE_FORM_ENDPOINT` | `#` | free-scan form POST target; `#` keeps the mailto fallback |
| `SITE_YEAR` | build year | footer copyright |
| `SITE_SAME_AS` | GBP permalink | comma-separated profile URLs for schema `sameAs` |
| `SITE_GBP_URL` | GBP permalink | Google Business Profile link (`sameAs`, `hasMap`, contact page) |
| `SITE_GEO` | *(unset)* | `"lat,lng"`; omitted for a service-area business |
| `SITE_HOURS` | *(unset)* | e.g. `Mo,Tu,We,Th,Fr 08:00-17:00`; must match GBP exactly |

`SITE_SAME_AS`, `SITE_HOURS` and `SITE_GEO` are omitted from the schema when unset.

See `.env.example`.

## Assets

Fonts are self-hosted in `site-src/static/fonts/` (latin subset). To change weights:

```bash
curl -A "Mozilla/5.0 (X11; Linux x86_64) Chrome/120" \
  "https://fonts.googleapis.com/css2?family=Barlow+Condensed:wght@600;700;800;900&family=Barlow:wght@400;500;600;700&display=swap"
# take the /* latin */ blocks, download each woff2 into site-src/static/fonts/,
# and update the @font-face rules at the top of site-src/main.css
```

CSS and JS are content-hashed (`main.<sha>.css`) and cached immutable for a year.

`site-src/lastmod.json` holds a content hash and date per page; the date only
moves when the body changes. Commit it with content edits.

## Dokploy

Use the **Application** type with a **Dockerfile** build, not Nixpacks.

1. **Project → Create Service → Application.**
2. **Source:** point at the Git repo (this directory must be the repo root, or set
   *Build Path* / *Base Directory* to `serpens-studio-site`).
3. **Build Type:** `Dockerfile`, path `./Dockerfile`.
4. **Build Args** — only what differs from the defaults:
   ```
   SITE_BASE_URL=https://serpens.studio
   SITE_FORM_ENDPOINT=https://…
   ```
5. **Domains:** add `serpens.studio` → **container port `80`**, HTTPS on,
   certificate provider Let's Encrypt. Traefik terminates TLS; nginx speaks plain
   HTTP internally, hence `absolute_redirect off` in the config.
6. **Deploy.** Health check is built in (`GET /healthz` → `ok`).

### www and apex

`www` currently answers 200, serving the site on a second hostname.
`nginx/site.conf` 301s it to the apex, so add **both** `serpens.studio` and
`www.serpens.studio` as Dokploy domains on container port 80. Attaching only the
apex also works, but then existing www links die instead of redirecting.

### Cutting over from the previous site

The previous site had six indexed URLs. Four have no equivalent here and would
404 on deploy, so `nginx/site.conf` 301s them:

| old URL | goes to | why |
|---|---|---|
| `/` | `/` | unchanged |
| `/about` | `/about/` | handled by the trailing-slash rule, no explicit entry |
| `/services` | `/pricing/` | nearest intent match |
| `/work` | `/results/econ-windows/` | the portfolio is now the case study |
| `/work/scoutmap` | `/results/econ-windows/` | project retired |
| `/work/meridian` | `/results/econ-windows/` | project retired |

Keep these permanently. Check Search Console's Pages report a few weeks after
launch and add any other 404s that used to rank.

### Submitting the sitemap

Search Console is DNS-verified at the domain level, covering http, https, www and
apex in one property. Nothing to re-verify after cutover.

1. Deploy first. Submitting a sitemap whose URLs 404 wastes the crawl.
2. Search Console → **Sitemaps** → enter `sitemap.xml` → Submit.
3. **URL Inspection → Request indexing** on `/` and any priority pages.

`google.com/ping?sitemap=` no longer works; Google retired it in 2023. Submit via
Search Console or its API. `robots.txt` also advertises the sitemap.

### Redeploying

`dist/` is gitignored and rebuilt in the image, so a push is enough. HTML is
`no-cache`; assets are content-hashed, so a redeploy is picked up immediately.

## Free-scan form (Resend)

The site is static, so `RESEND_API_KEY` cannot live in it — anything passed as a
build arg is baked into public HTML. The key belongs to `form-handler/`, a small
service nginx proxies at `/api/scan`.

Deploy `docker-compose.yml` as a Dokploy **Compose** service to get it:

```
web   nginx + the built site, domain attached here, port 80
form  the endpoint; not published to the host, reachable only through nginx
```

Set these in Dokploy's **Environment** tab (runtime env, NOT build args):

| var | notes |
|---|---|
| `RESEND_API_KEY` | required; the compose file refuses to start without it |
| `MAIL_TO` | default `hello@serpens.studio` |
| `MAIL_FROM` | default `Serpens Studio <scan@serpens.studio>`; the domain must be verified in Resend |
| `RATE_LIMIT` | posts per IP per hour, default 5 |

`SITE_FORM_ENDPOINT` defaults to `/api/scan` in the compose file, so the POST is
same-origin: no CORS, no second domain, and the key is never reachable from a
browser. The handler validates and truncates every field, strips control
characters (so a name can't inject mail headers), drops honeypot submissions
while returning 200, and rate-limits per IP.

Deploying the **Dockerfile alone** still works — `/api/scan` simply 404s and
`main.js` falls back to composing a mailto. Nothing breaks.

## What the server config does

- **Clean URLs.** `/pricing/` → `/pricing/index.html`. `/pricing` gets a **301** to
  `/pricing/`, only when the directory exists so typos 404 directly. One URL per page.
- **404 / 403.** Both serve the branded `/404.html` with a 404 status. Index-less
  directories (`/results/`, `/img/`) and dotfiles can't produce a 403 leak.
- **Caching.** HTML `no-cache`; hashed CSS/JS immutable 1 year; images and fonts 30 days;
  `robots.txt` / `sitemap.xml` 1 hour.
- **Security headers.** `nosniff`, `SAMEORIGIN`, `strict-origin-when-cross-origin`,
  a `Permissions-Policy`, and a CSP. The CSP allows `'unsafe-inline'` for scripts and
  styles because the pages use inline `style` attributes, inline `onerror` image
  fallbacks, and inline `application/ld+json`. `connect-src`/`form-action` permit an
  off-site `SITE_FORM_ENDPOINT`. Removing `'unsafe-inline'` means refactoring those
  out of `site-src/home.html` and `build.py` first.
- **gzip** on all text types. No brotli — `nginx:stable-alpine` ships without it;
  Traefik can compress instead if you want it.
